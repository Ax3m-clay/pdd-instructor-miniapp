# ИИ-инструктор ПДД — Telegram Mini App

Помощник для теории в автошколе: берёт следующий урок с учебной платформы,
делает из него выжимку на 5 минут через LLM и отвечает на вопросы как
«инструктор ПДД» с учётом текущего урока. Бот сам ничего не пишет — всё
происходит в мини-апке по кнопке **Open** в Telegram.

Крутится на моём домашнем сервере (Proxmox, VM на Debian 13), пользуюсь
каждый день. Ниже в основном про инфраструктуру: как это развёрнуто, почему
так, и что делать, когда что-то ломается.

## Архитектура

```
Telegram ──кнопка Open──> Tailscale Funnel :443 ──> helper :8790 (мини-апка)
                                                       │
                                     xray :10808 <─────┤ Telegram Bot API (через VPN)
                                                       ├─> API учебной платформы
                                                       └─> LLM API (OpenAI-совместимый)
```

| Сервис | Что делает |
| --- | --- |
| `helper` | Python, только стандартная библиотека. `8787` — служебный API, `8790` — мини-апка с проверкой подписи Telegram `initData` |
| `xray` | VPN-клиент (VLESS + Reality): доступ к Telegram API из сети, где он заблокирован |

## Инфраструктурные решения

**Без белого IP.** Домашний сервер за NAT провайдера. Наружу HTTPS отдаётся
через Tailscale Funnel: TLS-сертификат и домен — без открытых портов на
роутере и без VPS.

**Порты только на `127.0.0.1`.** Docker публикует порты в обход `ufw`, поэтому
все порты привязаны к localhost. Наружу выходит только мини-апка, и только
через Funnel.

**Контейнер не от root.** Отдельный пользователь `app`, папка для данных
создаётся с нужным владельцем ещё при сборке образа — том на чистом сервере
сразу доступен на запись. `HEALTHCHECK` дёргает `/health`, `docker compose ps`
показывает реальное состояние сервиса, а не просто «процесс запущен».

**SQLite, а не PostgreSQL.** Пользователь один, VM — 2 ГБ памяти. Отдельный
сервер БД здесь — лишний процесс и лишняя память. Переезд на PostgreSQL имеет
смысл, когда появится нагрузка.

**VPN с автопереключением и откатом.** Сервис VPN периодически меняет серверы
и ключи, из-за чего туннель однажды молча перестал работать. Теперь:
- `xray/gen_config.py` собирает конфиг из всех серверов подписки; xray раз в
  минуту проверяет их через туннель и ходит через самый быстрый живой
  (`observatory` + балансировщик `leastPing`);
- `xray/update_xray.sh` раз в сутки (systemd-таймер) пересобирает конфиг по
  схеме безопасного деплоя: собрать → `xray -test` → подменить → проверить
  туннель → откатить, если не работает.

**Секреты вне репозитория и образа.** Токены — в `helper/autoschool.env`
(`env_file` в compose), `.dockerignore` не пускает их в образ, конфиг VPN с
ключами генерируется на сервере и лежит в `.gitignore`.

## CI

`.github/workflows/build.yml` на каждый пуш в `main`:
1. проверяет синтаксис Python;
2. собирает Docker-образ;
3. проверяет, что контейнер работает не от root.

Сломанный Dockerfile или случайно убранный `USER` ловятся до сервера.

> В рабочей версии есть ещё деплой: self-hosted runner на VM делает
> `git pull` + `docker compose up -d --build` и ждёт, пока сервис станет
> `healthy`. Здесь он убран: self-hosted runner нельзя подключать к публичному
> репозиторию — код из чужого pull request выполнился бы на моём сервере.

## Данные

SQLite `/data/autoschool.db` в именованном томе `helper-data`:

| Таблица | Что в ней |
| --- | --- |
| `lessons` | уроки, статусы, выжимки |
| `kv` | настройки и служебные отметки (владелец, время синка) |
| `chat_messages` | переписка с инструктором |

Статусы уроков синхронизируются с платформой. Тесты к урокам человек сдаёт сам
на сайте — мини-апка только помогает подготовиться.

## Запуск

```bash
cp helper/autoschool.env.example helper/autoschool.env   # заполнить, chmod 600
docker compose up -d --build
sudo tailscale funnel --bg --https=443 http://127.0.0.1:8790
```

`WEBAPP_URL` в env — адрес Funnel: при старте helper сам ставит боту кнопку
меню **Open**. Мини-апка отвечает только владельцу: первый, кто открыл её после
чистой установки.

VPN-конфиг и таймер обновления:

```bash
echo 'https://…ссылка-на-подписку…' > xray/subscription.url && chmod 600 xray/subscription.url
sudo ./xray/update_xray.sh
sudo cp xray/systemd/xray-update.* /etc/systemd/system/   # поправить путь в .service
sudo systemctl daemon-reload && sudo systemctl enable --now xray-update.timer
```

## Структура

```
compose.yaml                 xray + helper
.github/workflows/build.yml  CI
helper/
  Dockerfile
  autoschool_helper.py       уроки, LLM, Telegram, синк с платформой, SQLite
  webapp/webapp.py           API мини-апки + проверка подписи initData
  webapp/static/index.html   фронт мини-апки (один файл, без зависимостей)
  autoschool.env.example     переменные окружения
xray/
  gen_config.py              конфиг xray из VPN-подписки
  update_xray.sh             обновление конфига с проверкой и откатом
  systemd/                   таймер раз в сутки
```
